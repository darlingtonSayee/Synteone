# Synteone Deployment Guide

Last updated July 28, 2026

## Production Shape

This repository contains:

- Public static pages: `index.html`, `about.html`, `products.html`, `projects.html`, `contact.html`, `privacy.html`, `terms.html`, and `page.html`
- Admin UI: `admin.html`, `admin.js`, `admin-activate.html`, and `admin-activate.js`
- Local Node backend for development: `server.js`
- Cloudflare Pages Functions production backend: `functions/[[path]].js`
- D1 database migration: `migrations/0001_synteone_cms.sql`
- Clean Cloudflare build output: `dist/`, generated by `npm run build`

The Cloudflare production backend stores CMS settings, pages, projects, contact messages, admin users, sessions, rate limits, and uploads in D1 through the `DB` binding.

## GitHub Setup

GitHub CLI is not installed in this workspace and no Git remote is configured yet.

To publish the repository:

```powershell
git add .
git commit -m "Launch Synteone website"
git branch -M main
git remote add origin https://github.com/<OWNER>/<REPO>.git
git push -u origin main
```

Replace `<OWNER>/<REPO>` with the GitHub repository you create.

## Cloudflare D1 Setup

Create the database:

```powershell
wrangler d1 create synteone-cms
```

For local Wrangler development, copy `wrangler.d1.example.toml` to `wrangler.toml`, then copy the returned `database_id` into `wrangler.toml`, replacing `REPLACE_WITH_CLOUDFLARE_D1_DATABASE_ID`.

Apply the schema:

```powershell
wrangler d1 migrations apply synteone-cms --remote
```

## Cloudflare Pages Setup

In Cloudflare:

1. Go to Workers & Pages.
2. Create a Pages project.
3. Connect the GitHub repository.
4. Set production branch to `main`.
5. Framework preset: None.
6. Build command: `npm run build`.
7. Build output directory: `dist`.
8. Add the D1 binding:

```text
Binding name: DB
Database: synteone-cms
```

Cloudflare Pages supports GitHub integration and automatic deployments when a repository is connected. Cloudflare's current docs also state that projects without a framework can leave the build command blank and use the repository root as the deployable output.

## Domains

Use these custom domains on the Cloudflare Pages project:

- `www.synteone.com` for the public website
- `admin.synteone.com` for the admin entry point

The Pages Function redirects `admin.synteone.com/` and `/admin` to `admin.html`. The admin API remains same-origin under `/api/admin/*`.

## Required Production Secrets

Do not commit these values:

- `ADMIN_PASSWORD` or `ADMIN_PASSWORD_HASH`
- `OPENAI_API_KEY`
- EmailJS private/access token

Set them in the Cloudflare Pages project environment variables:

```text
ADMIN_EMAIL=admin@synteone.com
ADMIN_PASSWORD=<long unique password>
ADMIN_ROLE=super_admin
OPENAI_API_KEY=<rotated OpenAI key>
OPENAI_MODEL=gpt-4.1-mini
```

Because an OpenAI key was pasted during setup, rotate that key before production launch.

## Cloudflare Access

Before launch, protect `admin.synteone.com` with Cloudflare Access or equivalent authentication in addition to the app login. This keeps the admin portal away from the public internet.
